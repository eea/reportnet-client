    QC rules

    For custodians writing SQL quality rules on a design dataset. Needs a login token, not an API key: create the client with ReportnetClient.from_tokens(). See Writing SQL QC rules for a walk-through, including what Reportnet does not check.

    qc = client.for_dataflow(11468).qc(48100)
qc.add_sql_rule("SITE01", name="Site code present", on="Sites",
                sql='SELECT * FROM dataset_48100."sites" WHERE sitecode IS NULL',
                message="Every site needs a code", severity="ERROR")

    QcDesigner

    Change one design dataset's SQL QC rules. Obtain via :meth:DataflowClient.qc.

    rule_set 

    rule_set() -> RuleSet

    All rules of this dataset's schema, as Reportnet lists them now.

    rules(*, sql_only: bool = False) -> list[RuleDefinition]

    The rules, automatic ones included unless sql_only.

    rule 

    rule(ref: RuleRef) -> RuleDefinition

    One rule by short code (case-insensitive) or object, freshly read.

    add_sql_rule 

    add_sql_rule(
    short_code: str,
    *,
    name: str,
    sql: str,
    on: Target,
    message: str,
    severity: Severity | str = Severity.ERROR,
    description: str = "",
    enabled: bool = True,
    record: bool = False,
) -> RuleDefinition

    Add an SQL rule; returns it as read back.

    on decides the rule type: a table (or its name) gives a TABLE rule, or a RECORD rule with record=True; a field, or (table, field) names, gives a FIELD rule.

    message: str | None = None,
    severity: Severity | str | None = None,
    description: str | None = None,

    Change an SQL rule; sends the whole rule (read-modify-write).

    enable 

    enable(ref: RuleRef) -> RuleDefinition

    Switch an SQL rule on.

    disable 

    disable(ref: RuleRef) -> RuleDefinition

    Switch an SQL rule off without deleting it.

    delete_rule 

    delete_rule(ref: RuleRef) -> None

    Delete an SQL rule; checks that it is gone afterwards.

    test_sql 

    test_sql(
    sql: str, *, provider_code: str | None = None
) -> Any

    Test-run sql on this dataset and return Reportnet's answer.

    Not verified. On the sandbox it failed on a dataset whose columns include a reserved word (Group): Reportnet's own wrapper leaves column names unquoted (2026-11-13).

    validate_all 

    validate_all() -> None

    Ask Reportnet to re-check every SQL rule of this dataset.

    It runs in the background, and on the sandbox it marked invalid SQL as verified: true. Do not read verified as "the SQL is valid".

    RuleDefinition dataclass

    One QC rule of a design dataset, as GET /rules/{schemaId}/dataflow/{id} lists it.

    Not :class:~reportnet.QcRule, which is parsed from the public schema spreadsheet and has different fields.

    is_sql property 

    is_sql: bool

    True for a rule whose logic is an SQL sentence.

    to_body 

    to_body(**changes: Any) -> dict[str, Any]

    The create/update body the web app sends, with changes applied.

    Keys are the API's (ruleName, sqlSentence, thenCondition, …). A TABLE rule also gets "integrityVO": null, as in the web app.

    RuleSet dataclass

    All QC rules of one dataset schema.

    by_short_code 

    by_short_code(short_code: str) -> RuleDefinition | None

    The rule with this short code (case-insensitive), or None.

    Severity

    Bases: str, Enum

    Level of a QC rule's message (thenCondition[1]).

    (str, Enum) rather than StrEnum: the library supports Python 3.10.

    Raw client methods

    One ReportnetClient method per endpoint, without the designer's guards or read-back.

    get_rules 

    get_rules(*, schema_id: str, dataflow_id: int) -> RuleSet

    GET /rules/{schemaId}/dataflow/{dataflowId} — every QC rule of a schema.

    Lists automatic and manual rules. schema_id is :attr:DesignDataset.schema_id, not the dataset id.

    create_rule 

    create_rule(
    *, dataset_id: int, body: Mapping[str, Any]
) -> None

    PUT /rules/createNewRule — add a rule (yes, PUT).

    The answer is empty: no rule id is returned. Find the rule afterwards by its shortCode in :meth:get_rules.

    update_rule 

    update_rule(
    *, dataset_id: int, body: Mapping[str, Any]
) -> None

    PUT /rules/updateRule — replace a rule; also how it is enabled or disabled.

    Send the whole body, with ruleId (:meth:RuleDefinition.to_body <reportnet.RuleDefinition.to_body>).

    delete_rule 

    delete_rule(*, dataset_id: int, rule_id: str) -> None

    DELETE /rules/deleteRule — remove a rule.

    datasetId is the numeric dataset id. The schema id, which the web-app code suggests, answers 400 (sandbox, 2026-11-13).

    evaluate_sql_rule 

    evaluate_sql_rule(
    *, dataset_id: int, sql: str
) -> float | None

    POST /rules/evaluateSqlRule — Reportnet's cost estimate for sql.

    Not a validity check: it answered 0.0 for valid and invalid SQL alike (sandbox, 2026-11-13). To find invalid rules, run :meth:validate_sql_rules and read verified and sqlError.

    run_sql_rule 

    run_sql_rule(
    *,
    dataset_id: int,
    sql: str,
    show_internal_fields: bool = False,
    provider_code: str | None = None,
) -> Any

    POST /rules/runSqlRule — test-run sql and return the first rows.

    The server wraps the query (… as userSelect LIMIT 10). Pass provider_code to run it as that data provider. It reads; it does not change rules or data.

    validate_sql_rules 

    validate_sql_rules(
    *, dataset_id: int, schema_id: str
) -> None

    POST /rules/validateSqlRules — re-check every SQL rule of a dataset.

    Afterwards each rule's verified (and sqlError) is set; a new rule is verified: null until this has run. The answer is empty.

    get_rule_history 

    get_rule_history(
    *, dataset_id: int, rule_id: str
) -> list[dict[str, Any]]

    GET /rules/historicInfo — earlier versions of a rule.

    Answered [] on the sandbox even after three updates (2026-11-13).
